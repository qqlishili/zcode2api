# 测试 05 — 验收标准与发布门禁

## 1. 通用发布门禁（每个版本）

- [ ] CI 全绿：unit + interop + contract + integration（Mock 上游）
- 全量入口与 `.github/workflows/ci.yml` 保持一致；局部回归不能替代 GitHub CI。每项测试独立持有账号连接池，测试响应具备异步关闭契约，后台额度请求与模型 POST 分别核验。
- [ ] 覆盖率：`app/` ≥ 85%，关键纯逻辑模块 ≥ 95%，classify/pool 分支 ≥ 90%
- [ ] ruff / mypy-basic 0 error
- [ ] E2E 套件通过（compose 全栈）
- [ ] 真实上游冒烟通过（含生成 / 可选领取，须明确授权，见测试文档 04 §4）
- [ ] 变更涉及加密/封包 → 对拍输出附 PR（测试文档 03 §4）
- [ ] 变更涉及上游分类/池行为 → 对应 CLASSIFY-*/POOL-* 用例先行更新（行为变更与用例变更同 PR）
- [ ] `.env` / `data/` / 向量口令不入镜像与仓库（CI 断言 + 人工复核）
- [ ] 文档同步：02 移植映射勾选、05 协议如有实测修订、CHANGELOG 条目

## 3. 性能与稳定性基线

- 单实例（测试基线：2 核 / 4 GiB，实际 VPS 另行测量）：≥ 30 并发流式请求无 5xx（Mock 上游）；内存 RSS < 400MB
- 转发开销：P95 增幅 < 15ms（TTFB 对比直连 Mock）
- 72h 长跑（Mock）：无内存增长（泄漏阈值 < 10%）、无句柄泄漏、池状态无漂移
- 验证码求解缓存命中率（持续负载下）> 90%

## 7. 验证码诊断与调度修复

- Node 纯校验和 Python 摘要边界：有效/短/缺token/非法JSON/无摘要退出6，默认及DEBUG摘要无夹具秘密；未知输入安全回退，不削弱原校验。
- 真实manager Events 与临时Node：退避释放槽、合法11秒等待、原CPU上限、后台让位及恢复、单飞广播、等待者取消隔离、配置/排队/执行独立预算、close无遗留进程或未消费异常。
- 出口与网络：同请求同出口失败只求解一轮且不挡健康其它出口，有效池优先；本地错误不熔断，查询不占半开资格，网络边界只放一个探针，取消可重入，quota三并发一次结算。
- 真实TCP Mock：Messages/Chat/Responses × stream真假，混合验证码/额度/transport、尝试覆盖缺口、换号成功；公开错误无内部细节，监控快照隔离且最多32条，账号槽和原Retry-After语义保持。
- 本地浏览器：新旧/未知/恶意HTML记录可读、键盘展开、窄屏显示；刷新/展开只GET监控，无验证码/模型/额度副作用。实际浏览器证据与离线测试分别记录。
- 经授权VPS：当前E个独立出口各一次验证码及真实模型调用，后台补货开启再跑10条并发2；逐出口成功、批次10/10非空与正常终态，503/429/排队或预算失败0，双核最大活跃Node1，负载结束补货恢复。用实际客户端入口及req_id关联监控/journal，不能用本机Mock或VPS-local探活充当恢复。
- 发布保留旧代码/Node模块与启动参数完整副本和哈希，隔离启动旧版验证回退；账号库与实际额度变化不回滚。部署重启短中断及监控清空必须记录。历史退出6细分类未知照实保留，任何真实失败先按新分类修复再复验。

## 8. 周期出口探测隔离

- 导入前设置临时 `ZCODE_DATA_DIR` 和 `PYTHON_DOTENV_DISABLED=1`，提供器/生命周期/scan/ENV/registry 与只读基础配置、订阅和网络目标全部隔离。保留原监听丢失红复现，验证无生产写入或服务命令；互斥前不外呼，取消/早退/超时回收本轮进程和监听。
- 来源用例覆盖重复来源、改名/排序、成功删除与另一来源失败、破损/空响应保留；完整 TLS/认证/传输/未知字段及类型变化产生新身份，旧部分指纹歧义停止。健康失败和观察超时不撤销来源或释放物理槽；无同区替代保留健康 fallback，同区满槽拒绝追加。
- 实际引用覆盖准入竞争、长 SSE 超过 idle TTL、正文/关闭、异常/取消/重试、producer 独立引用、启动前取消或 manager 关闭的零引用收尾、退役后的有效父操作现解、延后任务代次失配、固定引用及确认过期。一个等待者取消时仍运行的 producer 引用必须保留。HTTP 成功与 breaker 不代表排空；同端口新代次不得继承 token、client、结果或确认。
- Linux 使用 VPS 同版本实际 Mihomo、正式托管客户端/消费者和真实回环 TCP/SSE，长流横跨完整扫描、路由提交和退役，新业务使用同区替代。旧引用未完不删除；全部当前引用与实际连接归零后验证 reject、后续同区新代次复用。必须有非空内容、正常 DONE、零更新器业务失败，Windows skip 不计通过。
- 全部配置槽校验 reject/唯一身份/过滤与冲突边界，采集峰值 RSS/FD 及周期预算。故障仅在隔离实例注入：Controller 失效/拒绝/响应丢失、文件失败、watcher 先加载、SIGTERM/强制退出、注册表提交前/后及 reject 后中断、网关重启/worker 变化。基础配置/PID/监听不变，提交前恢复、提交后向前，未知状态冻结且证据保留。
- 生产源码绑定实际 Antigravity CLI 固定包回执与 Git 本机/远程/VPS 提交、运行哈希。首次一次维护先核对并排空消费者，记录真实暂停区间；维护后完整手工周期覆盖实际客户端非流式/流式请求，用 req_id 对齐监控/journal。有效验证码、非空正常模型终态及无更新器造成的 503/连接失败才能恢复 timer。
- 首次加载前核对业务槽与系统临时源端口范围/既有预留；在隔离网络命名空间复现源端口占用导致 bind 失败，验证合并预留后自动分配避开业务槽。生产全部监听与原 PID、预留及私有回退均须实核，不能以 `/configs` 成功替代监听完整性。
- 额度前提不足记录真实业务验收受阻，不改额度或放宽通过条件。回退旧缺陷脚本保持 timer 暂停，基础结构回退使用维护窗口；生产数据/秘密/私有副本不入库，规划 SHIP 和原型不能替代实施或运行验收。
