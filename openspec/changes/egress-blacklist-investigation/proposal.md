# 调查代理出口被上游 3012 拉黑的判定依据

## 现象（2026-10-15 实测）

出口探针单轮结果：**29 个候选出口里只有 2 个可用**，其余 27 个一律返回
`HTTP 405` + 业务码 `3012`：

```
http://127.0.0.1:21100 → 405 code=3012（该出口已被上游拉黑）
http://127.0.0.1:21101 → 405 code=3012
http://127.0.0.1:21102 → 405 code=3012
http://127.0.0.1:21104 → 405 code=3012
http://127.0.0.1:21300 → 405 code=3012
http://127.0.0.1:21301 → 405 code=3012
...
可用: 2/29
```

**端口成段规律**：`21100/21101/21102/21104` 同段全灭，`21300/21301` 另一段也全灭。
这不像"逐个节点被拒"，更像**按 IP 段或出口供应商**判定。

## 为什么值得单独调查

出口是**能否服务**的前提条件之一（另一个是官方 dress，已由插件通道提供）。
目前只有 2 个可用出口，意味着：

- 全部请求挤在 2 个出口上 → 频率特征集中，反而更容易触发风控
- 一旦这 2 个也被拉黑 → 只能直连 VPS 真实 IP（当前兜底策略），真实 IP 暴露
- 探针每轮只扫账号实际用到的大区，所以"2/29"就是**当前实际可用面**

## 待回答的问题

1. **3012 的判定依据是什么？** 出口 IP 段？ASN？TLS 指纹？请求特征？
2. **拉黑是永久的还是有时效？** 已拉黑的端口过一段时间能否恢复？
3. **同一 IP 段里为什么有少数幸存？** 幸存者与全灭者的差异在哪（入口端口号、
   物理机、线路）？
4. **能否规避？** 例如换端口、换供应商、控制单出口频率、避免并发特征。
5. **我们的使用方式是否在加速被拉黑？** 需核对：单出口并发、请求间隔、
   是否复用同一 TLS session。

## 范围

**只做调查与结论**，不在本 change 内改动生产选路逻辑。若调查得出可执行的
规避措施，另开 change 实施。

## 追加证据（2026-10-15 交叉分析）

### 事实（可直接复核的数据）

**端口按大区成段，每区 100 个**（`data/egress_registry.json`）：

```
HK 21100-21199    TW 21200-21299    JP 21300-21399    SG 21400-21499
US 21500-21599    KR 21600-21699    EU 21700-21799    OTHER 21800-21899
```

**探针单轮结果（29 条记录，只覆盖账号所在的大区）**：

| 大区 | 探测数 | 可用 | 被拒（3012） |
|---|---|---|---|
| HK | 4 | 0 | 4 |
| JP | 19 | 0 | 19 |
| TW | 6 | **2** | 4 |

可用端口：`21200`（账号 akbgpryk）、`21202`（账号 bwumo4lp）。

### 关键反例：同账号跨出口结果不同

```
akbgpryk:  21308 ❌   21200 ✅     ← JP 被拒、TW 成功
bwumo4lp:  21310 ❌   21202 ✅     ← 同上
nqdgpeby:  21309 ❌   21201 ❌     ← TW/JP 都失败
```

前两条**排除**了「出口整体不可用」的简单解释：若 21200 是坏出口，
它对 akbgpryk 也不该成功。但第三条又说明**部分账号在 TW 也被拒**。

**即两个因素同时存在**：出口侧（HK/JP 段整体不可用）与账号侧（个别账号被标记）。

### ⚠️ 探针设计缺陷（本 change 的第一个产出）

**当前探针的「账号轮换 × 出口」配对使结果无法归因**：

```
交叉矩阵:  13 账号 × 29 出口 = 377 格，实际只有 29 格
空档率:    92%
被 ≥2 个账号测过的出口:  0 个
```

**每个出口只被 1 个账号测过** → 结构上无法区分「出口坏」与「账号被标记」。

**修法（待评估）**：同一出口至少用 2 个不同账号探测（交叉验证）。
**代价**：探测量翻倍（当前一轮约 33 秒 → 约 66 秒），且每个账号多消耗一次配额。

**这个 trade-off 需要单独决定**，不纳入本 change 的调查范围。
