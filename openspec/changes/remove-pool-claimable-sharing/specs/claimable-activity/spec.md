# Spec Delta

## Purpose

确保管理页面和自动领取使用当前账号自身的上游活动资格，避免把其他账号已持有或可领取的活动传播给本号。查询、缓存和页面切换保持账号边界，保留本号真正可领取的其他活动。

## ADDED Requirements

### Requirement: 本号活动资格
系统 SHALL 仅从本号上游 preview 结果生成自动领取候选，排除本号已持有的套餐。其他账号已持有或可领取的活动 MUST NOT 为本号增加资格；探查结果仅同步本号。

#### Scenario: 他号持有活动而本号 preview 为空
- **WHEN** 账号 A 持有活动，账号 B 的 preview 成功返回空列表
- **THEN** B 的待领列表为空，不广播 A 的活动，也不为 B 发起该活动的自动领取

#### Scenario: 本号具有其他活动资格
- **WHEN** B 的 preview 返回本号尚未持有的活动
- **THEN** 仅 B 的待领列表出现该活动，已持有项被排除，A 的资格不因此改变

### Requirement: 自动领取逐号核验
系统 SHALL 在自动领取时重新查询目标账号自身的 preview。哨兵发现某账号的新活动后，MUST NOT 直接将该活动作为其他账号的领取目标。

#### Scenario: 自动领取时本号没有资格
- **WHEN** 哨兵发现活动，但目标账号自己的 preview 没有待领项
- **THEN** 目标账号跳过领取，不消耗验证码或向领取接口提交该活动

### Requirement: 页面候选保持本号边界
系统 SHALL 以本号待领项显示领取条和候选菜单。成功取得本号新 preview 后，MUST 用新结果替换旧候选；切换账号时 MUST 清除上一账号的选择及手填目标，且旧账号晚返回的查询不能覆盖当前账号菜单。

#### Scenario: 空结果清除旧候选
- **WHEN** 本号缓存有旧候选，但新的 preview 成功返回空列表
- **THEN** 菜单不再推荐旧候选，并清除由旧候选预填的目标

#### Scenario: 切换账号
- **WHEN** 弹窗从有资格的 A 切换到无资格的 B
- **THEN** B 不显示 A 的候选或预填目标，并查询 B 自身的 preview

#### Scenario: 上一账号请求晚返回
- **WHEN** A 的 preview 在弹窗已经切换到 B 后返回
- **THEN** 该响应不覆盖 B 的候选菜单

### Requirement: 显式手动领取保持兼容
系统 SHALL 保留显式输入活动标识的手动领取入口，由上游判断最终资格；显式输入不构成该活动可领取的证明，也不能广播为其他账号的候选。

#### Scenario: 手动指定未缓存的活动
- **WHEN** 用户显式输入本号缓存中不存在的活动标识
- **THEN** 系统保留上游资格校验，不根据池内其他账号推断或传播可领取状态
