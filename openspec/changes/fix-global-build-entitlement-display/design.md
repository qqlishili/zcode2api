# Design

## 决策

- 保留现有按套餐隔离的 `plan_slots.items/pending`；pending 只表示对应余额桶未生成，不代表时间尚未生效。逐权益比较 effective_at：未来显示“未生效”，时间已到或未知显示“待结算”。只展示授予量，不伪造 remaining/百分比。
- 两种已有渲染入口共用一个授予量行函数；旧数据无槽位时保留余额展示，对无对应模型余额的权益展示待结算，未来权益仍单独展示。旧数据只有模型合并余额，不能用于证明同名模型的跨套餐结算归属；刷新得到完整槽位后按套餐展示。
- 保留现有款式与 DOM；EXHAUSTED 账号的等待文案映射为“待生效/待结算”徽章，状态枚举不变。ACTIVE 账号仍显示正常，无论是否另有待生效活动。
- 领取资格继续只信本号 preview 与持有套餐过滤，不重新引入池内共享推断。

## 验收

使用页面原始 JS 的 happy-dom 行为测试，固定时间覆盖未来、过去、未知时间、到账后、双活动同模型余额、旧数据、徽章和资格过滤。结合真实管理 API 的两个指定账号及上线页面验证，不宣称视觉或浏览器兼容性通过；真实新活动到账由原待办单独跟踪。
