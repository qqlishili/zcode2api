# Spec Delta

## Purpose

让管理页面和原生服务日志呈现与网关实际判定同源的失败原因、停止覆盖及验证码阶段摘要，使用户能够由请求标识核对失败，并保持公开三协议兼容、后台证据有界及旧记录可读，避免通用错误文案造成错误归因。

## ADDED Requirements

### Requirement: 管理页面显示结构化失败而不是只显示通用文字

管理请求监控 MUST 在失败记录中显示可读原因摘要，并允许用户查看请求标识、错误码、原子原因、来源、停止原因、重试建议与覆盖状态。含验证码证据时 MUST 展示本次阶段、安全类别、尝试次数和等待/执行时间；未知信息明确为未知。只有实际证据含 `local_concurrency_limit` 时才能展示账号并发已满。

#### Scenario: 有额度但验证码失败
- **WHEN** 最终 503 记录包含 `captcha_error` 与其它账号额度耗尽，且没有本地并发原因
- **THEN** 页面 MUST 显示验证码获取失败与额度排除的混合原因
- **AND** 不得把验证码求解排队解释为账号并发已满或全部账号额度耗尽

#### Scenario: 求解停止与最后失败不同
- **WHEN** 验证码证据的最终停止原因是预算耗尽，最后求解器类别为参数过短
- **THEN** 页面 MUST 分别显示等待/预算停止及最后已知校验类别，不能合并成一个错误结论

#### Scenario: 尝试上限存在覆盖缺口
- **WHEN** error_code 为 `dispatch_attempt_limit` 且覆盖不完整
- **THEN** 页面 MUST 显示尝试上限与未完成覆盖，不能宣称已证明全池不可服务

#### Scenario: 旧版或未知字段记录
- **WHEN** 记录只存在旧 error/status，或新增字段缺失、为空或包含未知类别
- **THEN** 页面 MUST 保持旧记录可读，未知类别安全显示，不能阻断其它记录渲染

### Requirement: 管理证据与服务日志可关联且保持公开兼容

系统 MUST 复用既有管理监控记录，以本次请求 ID 关联最终 503 与原生日志；验证码失败还 MUST 提供本次共享求解标识用于核对 producer 事件。新增验证码证据 MUST 仅出现在已鉴权管理记录与服务日志，维持既有最多 32 条证据、截断计数和独立快照语义。公开三协议响应的既有 code/causes/retryable/Retry-After 判定 MUST 保持不变，不能把本地获取失败改为已证实的上游挑战失败。

#### Scenario: 默认失败可由请求定位
- **WHEN** 某请求因验证码获取失败最终返回 503
- **THEN** 响应 request_id、X-Request-Id、管理 req_id 与最终 journal 日志 MUST 相同
- **AND** 管理验证码证据和该请求的安全失败日志 MUST 可用 solve_id 关联同一实际 producer

#### Scenario: 三协议兼容
- **WHEN** Messages、Chat Completions、Responses 分别以流式或非流式入参在输出前最终不可用
- **THEN** 保持 HTTP 503、既有错误类型和字段语义
- **AND** 新的内部验证码参数长度、求解标识、代理及耗时 MUST NOT 加入公开错误响应

#### Scenario: 获取失败与上游挑战分开
- **WHEN** 本地验证码获取失败，或者有效获取后上游连续挑战耗尽
- **THEN** 保留既有 `captcha_error` 与 `captcha_retry_exhausted` 的不同类别
- **AND** 新增细节不得凭空修改账号余额、风控、重试截止或原因来源

#### Scenario: 证据有界且快照隔离
- **WHEN** 多次挑战/换账号产生超过既有上限的证据，或者管理读取者修改收到的详情对象
- **THEN** 管理证据数量 MUST 受限并正确显示截断，读取者修改 MUST NOT 改变后续监控记录

### Requirement: 诊断展示安全且不产生额外业务副作用

新增诊断文本 MUST 作为转义文本渲染，可通过键盘展开查看，并在窄屏保持可读。刷新和查看诊断 MUST 只读取已有监控数据，不执行验证码验证、模型请求、额度刷新、账号恢复或诊断数据库写入。页面 MUST 明确请求监控为最近记录且重启可清空，不暗示持久审计日志。

#### Scenario: 恶意字段不会变成代码
- **WHEN** error、未知类别或旧记录含 HTML/脚本片段
- **THEN** 页面 MUST 展示转义文本，不执行脚本或创建危险 DOM

#### Scenario: 键盘和窄屏查看
- **WHEN** 用户用键盘展开一条失败记录或在窄屏查看
- **THEN** 必要的原因、请求 ID 和阶段 MUST 可读取，展开控件可聚焦并操作，不覆盖相邻数据

#### Scenario: 只查看诊断
- **WHEN** 用户刷新、筛选或展开请求监控
- **THEN** 只读取既有记录，不能因此产生新的上游业务请求或清空监控

#### Scenario: 后续候选成功
- **WHEN** 请求此前验证码或连接失败但后续候选成功
- **THEN** 页面 MUST 保持最终成功状态，不残留最终 503 原因字段或误标失败
