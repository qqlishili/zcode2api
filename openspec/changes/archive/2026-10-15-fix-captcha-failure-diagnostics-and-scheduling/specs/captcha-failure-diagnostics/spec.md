# Spec Delta

## Purpose

让验证码失败在默认运行模式下具有可核验且无秘密的类别和阶段，跨 Node 求解进程与管理侧传递本次求解证据，从而区分参数无效、执行失败和资源等待，避免依靠退出码或跨请求历史错误猜测根因。

## ADDED Requirements

### Requirement: 默认失败摘要可分类且不暴露秘密

系统 MUST 在求解进程已初始化的可控制失败路径中，不依赖调试开关输出一个版本化、长度不超过 2 KiB 的结构化失败摘要；进程在初始化前崩溃或被外部终止时 MUST 由调用方保留安全未知/不可用结果。摘要 MUST 仅包含允许的固定类别、阶段、实际退出码、参数字符数及耗时；无法可靠取得的值保持未知。系统 MUST 保持现有有效参数校验，拒绝空、过短、非预期 JSON 或缺失有效 securityToken 的结果。新增失败输出及相关校验异常 MUST NOT 包含验证参数、参数片段、securityToken、certifyId、凭据、cookie、请求内容、代理地址或原始 SDK/guest 错误正文。

#### Scenario: 默认模式发现降级参数
- **WHEN** 调试关闭且参数长度未达到现有有效门槛
- **THEN** 求解失败并输出参数过短类别、实际长度、提取阶段与对应退出码
- **AND** 不输出参数本身或前缀片段，也不产生成功验证输出

#### Scenario: 分开辨认无 token 与非法 JSON
- **WHEN** 参数满足长度门槛但有效 JSON 缺失或过短 securityToken，或者参数不能按现有规则解析为 JSON
- **THEN** 分别输出 `param_missing_security_token` 或 `param_not_base64_json`
- **AND** 结果继续被拒绝，不把两类失败统一说成 CPU 或账号额度问题

#### Scenario: 保持成功协议
- **WHEN** 求解进程完成并产生符合现有校验的参数
- **THEN** 保持成功 stdout 协议及成功退出，不额外公开参数到日志或诊断页面

#### Scenario: SDK 错误含秘密
- **WHEN** SDK/guest 错误对象或被拒参数中包含夹具凭据、certifyId 与 HTML 片段，且调试开关分别开启或关闭
- **THEN** 本次结构化摘要及校验异常仅留下固定类别和允许数字，不能包含夹具秘密或原始对象

### Requirement: 跨进程诊断必须校验并保留未知

系统 MUST 仅采纳已知前缀、版本、白名单字段及合法类型的摘要，并使用实际进程结果核对退出码。缺失、非法、超长或不支持的摘要 MUST 转为安全未知类，不能直接透传 stderr；退出码 6 本身 MUST NOT 被解释为具体某一参数失败。进程无法启动、无成功输出及执行超时 MUST 与已知参数校验失败区别记录。

#### Scenario: 历史求解器只有退出码
- **WHEN** 进程退出 6 且没有可采纳的结构化摘要
- **THEN** 诊断保留退出码并使用 `param_invalid_unknown`，不声称已经知道缺 token 或参数过短

#### Scenario: 伪造或损坏摘要
- **WHEN** stderr 包含任意原始异常、非法 JSON、未知版本、未知字段、退出码不符或超过上限的摘要
- **THEN** 仅采纳验证通过的字段或回退安全未知类，原始文本不能进入账号结果、journal 或管理证据

#### Scenario: 子进程不可用
- **WHEN** 求解器文件缺失、Node 无法启动、进程超时或未输出成功参数
- **THEN** 诊断记录对应运行阶段与可确定的安全类别
- **AND** 不把这些故障记为账号额度耗尽、账号凭据无效或已证实 WAF 封禁

#### Scenario: 本地失败不能充作网络证据
- **WHEN** 只有参数无效、SDK故障、排队/预算停止或安全未知类别，没有明确的出口网络失败证据
- **THEN** 新增诊断 MUST 保持本地/未知分类，不能推动代理熔断失败计数
- **AND** 不得通过匹配原始 stderr 地址字符串猜测并写入网络故障状态

### Requirement: 诊断属于本次共享求解并有界

系统 MUST 为每次实际共享求解提供关联标识和局部诊断；不同代理或并发求解 MUST NOT 借用另一求解的最后错误。诊断 MUST 区分最终停止 reason、最后已知求解器类别、尝试次数、排队时间、执行时间及总体时间；所有时间为有限非负值。被取消的等待者 MUST NOT 污染剩余等待者的成功或失败结果。

#### Scenario: 两个出口不同失败
- **WHEN** 出口 A 参数过短而出口 B 排队超时，且它们交错结束
- **THEN** A/B 分别取得各自求解的分类、次数和关联标识，不能因为全局最后错误变化互相串因

#### Scenario: 参数失败后等待耗尽
- **WHEN** 前一次尝试已取得参数无效类别，后续等待槽位超时或总预算耗尽
- **THEN** 最终 reason 表示排队或预算停止，最后求解器类别仍可独立查看
- **AND** 不把停止阶段虚构成一次新的参数校验失败

#### Scenario: 共享任务多等待者
- **WHEN** 多个请求等待同一实际求解且全部收到同一结果
- **THEN** 它们可以用同一求解标识关联实际事件，同时保持各自请求标识，新增诊断不包含账号身份
