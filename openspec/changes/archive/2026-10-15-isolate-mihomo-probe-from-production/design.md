# Design

## Context

动机见 `proposal.md`。原 updater 在探测初始化覆盖生产配置并重启，发布失败也自动重启；第一版未提交代码虽隔离了探测，仍通过生产 `PUT /configs` 发布及恢复，不能部署。目标版本 Mihomo v1.19.1 的实际隔离反例表明整份 `ApplyConfig` 有暂停窗口，非强制加载及保留 PID/SSE 不能保证新连接成功。file 提供器刷新、reject 空槽及删除后旧流存活已有隔离原型证据，不等于正式实现或生产验收。

用户已确定两项取舍：首次允许一次维护暂停，长期单生产实例；本轮包含客户端迁移、实际引用排空与旧槽安全回收。此前“客户端只核验兼容性”“旧槽永久保留”“周期非强制加载无损”的边界撤销，已完成的三项基线/红复现不重写为全任务完成。

规划时磁盘源码核对：`get_client()` 缓存命中绕过新注册表；`begin_request/end_request` 仅结算断路器；网关取客户端、等待验证码之后才 begin；`_Upstream.close()` 可复用为最终释放入口，网络成功回调不能代替流关闭。验证码 singleflight producer 与等待者生命周期不同；领取排队、安装、额度、全局配置获取也实际使用出口。该旧版缺少完整排空协议，实施及当前运行证据见 implementation。

## Goals / Non-Goals

**Goals:**

- 扫描、日常发布、失败恢复不改变生产基础配置、PID、固定监听或已有节点物理身份，不制造业务断流。
- 订阅成员关系、健康状态、路由准入和物理槽占用分别记账；删除来源不等于直接删除监听，健康失败不等于来源删除。
- 同一业务操作从选出口到验证码/上游结束保持同一身份；安全关闭旧准入、排空并复用槽，失败可核验恢复。

**Non-Goals:**

- 不补账号、重置额度、修改验证码算法、账号地域、并发或公开网关错误协议，不承诺外部节点/上游永不失败。
- 不新增数据库、第三方依赖、生产前置转发层、内核分叉、第二常驻生产实例或通用事务/租约服务。
- 未托管代理不改写；未知外部消费者或固定引用阻止相关槽自动回收，不推定连接数暂时为零就是无消费者。

## Decisions

### 1. 首次维护转换，日常固定槽提供器刷新

首次在明确维护窗口暂停项目业务准入及相关后台任务，排空并核对共享消费者，部署网关协议和代理结构。对基础配置做一次维护加载；仅在 Controller/进程确有必要且维护范围已确认时人工停启，不能把维护权限变成脚本日常重启回退。具体暂停时长以预演和实际记录为准。

复制完整生产基线，保留与本项目无关的 Controller、鉴权、规则、DNS 和监听。复用 `REGION_PORT_TIERS` 预建本项目各大区固定回环 mixed 监听，每端口指向独立 select 组；组用精确锚定前缀过滤一个私有 file 提供器。每个槽始终只匹配一个原节点或 reject 占位，禁止空组 COMPATIBLE/直连。已有占用槽保留完整连接定义；空闲槽和经确认已回收的同区槽才接纳新身份。冲突或资源预算不满足就停止迁移，不能强占其它服务。

日常仅原子替换提供器文件，并显式调用既有提供器 Update API，核验每个槽的唯一匹配/实际选中身份、原 PID 与实际监听归属；禁止 `/configs`、生产 stop/restart 或连接删除接口。基础配置哈希作为只读前提，外部改变时失败等待核对。file 提供器 `interval=0` 仍有 watcher：文件写入即可能生效，前置安全校验与待提交记录必须先完成，不能假定显式 Update 才是生效点。

替代方案：双生产实例增加生命周期、Controller、端口与网关交接成本，当前无业务使用不要求首次持续服务，因此不采用。只保留旧直绑监听无法自动接纳新节点；整份非强制加载的零失败前提已证伪。

### 2. 复用独立临时探测与受管生命周期

复用已安装 Mihomo，二进制取 `MIHOMO_BINARY` 或 PATH；私有临时配置/数据/Unix Controller、独立回环端口，不继承环境代理，不开启其它生产入站、DNS 或 TUN 接管。显式传递探测 URL 和控制客户端，绝不回退生产入口。配置先以独立 `-t` 校验，就绪核对进程、控制入口和监听归属；端口竞争有限重试，不抢占。

延续整轮非阻塞 `flock`，锁文件独立于被替换的 inode；timer、手工执行、恢复、退役清理共享完整更新资格。保持既有启动 10 秒、按候选数计算的扫描预算和 terminate 等待 5 秒再 kill/wait；oneshot 有限超时须容纳订阅读取、扫描、发布、确认与清理预算，`KillMode=control-group` 防止父进程强制退出后遗留。确认等待超过本轮预算只留下待退役状态，不强杀业务。

正常、异常、取消和 SIGTERM 都回收本轮子进程、连接与目录；stdout/stderr 不阻塞、摘要不泄密。无探测前提、设施错误、取消或未完成扫描不能转换成全部节点不健康。原节点筛选请求不是有效验证码和模型业务验收，真实外呼副作用在实施记录中如实说明。

### 3. 来源快照与完整身份归一化

最后有效完整快照保存在既有私有生命周期文件的版本化来源记录中，兼容迁移旧节点记录，不新增数据库。来源标识取既有配置项的稳定私有标识，重排不改变来源；订阅地址及凭据不入日志。成功响应必须有可信、完整、可解析的节点结构；超时、非成功响应、缺字段或截断保留该来源旧快照。合法空列表没有可验证证据时也保留并报告不确定；明确从配置中移除来源是删除其引用的证据。

节点身份用规范化完整连接定义计算：仅移除显示名及本程序生成的生命周期字段，映射键排序，保留认证、TLS、传输、协议扩展等连接字段和值的类型；不能随意裁剪未知字段或修改秘密大小写。规范化版本与旧指纹映射在首次维护中生成，同一完整定义沿用旧端口；歧义或旧部分指纹碰撞时停止，不猜测重绑。显示名/顺序/重复来源不产生新身份，任何影响连接的参数变化按新身份验证、旧身份退役。

成员集合为所有最后有效来源快照的并集。成功来源缺失某节点只撤掉该来源引用；失败来源保留引用。全部来源均撤销才标记待退役；探活失败只改变 active/stale 健康状态。既有观察时限可辅助健康诊断，不能删除来源快照、证明排空或直接触发物理回收。

新候选按既有分类/探测核实大区，先占安全同区空槽并加入提供器。无同区可服务替代时，保留仍可服务的旧节点作为明确标记的临时后备，并在后续有效轮次重评；旧节点也失效则沿用地域离线诊断，不跨区或直连。全订阅失败、扫描设施失败或无可发布出口不发布空注册表，保留最后完整路由并注明未重新验证；不能以失败作为成员删除证据。节点集合和路由不变的重复轮次不重写提供器或生成新路由版本，仅记录运行诊断。

### 4. 操作引用在选出口之前取得，流关闭后释放

复用 `AccountClientPool` 的锁和缓存，引入最小的操作上下文：`acquire_operation(account|managed_proxy)` 在同一个锁内读取完整已提交注册表、核验槽身份/准入、取得或创建客户端并增加引用，返回固定的客户端、实际代理、节点身份及发布版本；`release_operation` 幂等释放。上下文只是现有池的生命周期能力，不另造连接池。

注册表保持 `updated_at`、`regions` URL 列表；增加 `generation` 和 `slots` 身份元数据。每槽记录 `node_id`、`epoch`、`region` 与准入状态（active/draining/fallback/empty），generation 为包含这些准入字段的规范化路由/槽摘要，排除时间戳；读取以完整内容和版本核验，mtime 仅作优化。槽身份以端口、规范化节点指纹和身份代次共同限定；回收后同端口的新身份不能沿用旧代次。缓存按实际身份检查：仍有效的绑定不因其它节点新增而重建；失效绑定脱离新请求入口，新的操作选择同区替代。注册表不完整或身份不匹配时不能启用未验证端口。

取得客户端与操作引用不能分开；裸旧句柄无新操作资格，所有真实联网调用点必须迁移。延后执行的补货/固定代理任务在入队时携带节点/槽代次，执行时再核验；不接受仅凭旧 URL 将句柄重新标成新节点身份。静态显式固定 URL 没有代次时视为固定引用，阻止复用直至配置解除。已准入操作允许在旧节点完成其验证码、排队、重试及上游流，但不得把引用转给独立的新业务；切换出口需要结束该次尝试并重新准入、重新取得验证码。原 `begin_request/end_request` 继续负责断路器，不能把 breaker、账号并发槽或收到 HTTP 200 当引用释放。

| 消费者 | 引用边界与释放 |
| --- | --- |
| 网关 | 选客户端前取得，覆盖验证码等待、上游重试、正文/SSE；交给 `_Upstream.close()` 后只在其实际关闭完成时释放；本地失败、返回避让、异常、取消同样 finally 释放。 |
| 领取/安装/额度/活动上报 | 取得客户端前持有，覆盖排队与配对网络调用；验证码和领取使用同一实际身份；嵌套调用透传上下文而非再次选出口，所有 finally 配对。 |
| 验证码 | producer 创建前独立取得出口引用，直到 Node 子进程/配置外呼实际结束并回收才释放；等待者取消不得释放仍运行 producer 的引用。停止旧出口新补货和没有父操作的新 producer；已准入父操作在退役后才需要现解时，在同一锁内以其有效身份引用派生 producer 自身引用，不重新选出口、不被新准入关闭误拒绝，也不能授权独立新业务。未分配旧 token 定向失效，不迁到新身份。 |
| 全局配置/安装、显式代理及端口 | 使用托管槽时通过同一准入/引用接口，静态 `ZCODE_PROXIES` 不得绕过已提交注册表重新启用旧槽；未托管代理保持原行为但不能提供托管槽排空确认。 |

普通 idle prune、`close_account` 及退役关闭都先从可选缓存移除，实际引用归零后才 `aclose`；强制项目关停按既有生命周期处理，不能作为日常发布办法。后台任务通过当前应用 lifecycle 启停一个轻量本地协调任务，处理版本变化、停止补货、回收零引用缓存和更新确认，即使没有前台请求也能推进排空，不增加独立常驻服务。

### 5. 按当前进程与版本确认排空，再删除物理节点

协调记录位于既有私有数据目录；为本次退役请求保存 `request_id`、目标 generation、待退役槽身份和消费者集合。网关启动以 PID、系统进程启动标识及随机 `boot_id` 注册当前消费者，启动先加载当前路由、关闭已退役准入，再启动后台外呼。更新器核对实际服务进程/worker 与注册集合；旧版本消费者、独立运维消费者或未确认的显式固定引用阻止相应回收，不凭文件存在或心跳过期推定退出。

消费者在同一准入锁下应用目标版本并永久关闭该旧身份的新操作；随后停止补货、清理未分配 token，等待实际操作/producer 引用归零并关闭旧缓存。原子写确认，字段至少为 `request_id`、`boot_id`、PID/启动标识、`generation`、槽/节点身份、`admission_closed`、操作/producer/缓存引用计数及协议版本。确认只说明该进程范围，不能代替其它消费者。零引用后新拿到的旧裸句柄仍必须被准入栅栏拒绝。

更新器物理删除前再次核对：当前目标版本、消费者集合及启动身份未变；所有确认匹配本次 request_id 且计数为零；没有账号显式固定引用或未知消费者；实际 Mihomo 连接中无目标身份/槽。连接观测必须能关联本项目槽与节点；接口失效或无法归属就等待。不能以瞬间 TCP 零连接、固定等待小时数或过期确认复用端口。

将旧节点从完整提供器快照移除并填 reject，原子落盘及 Update 后核验目标组、旧节点缺失、监听仍归属原 PID。不改基础配置、不终止旧业务。只有持久记录确认 reject 且排空证据仍有效，才进入可回收状态；后续发布才能复用同区槽。每次新身份都重新验证，清除该槽旧身份的 breaker/token/缓存状态；跨区借槽和未经排空覆盖禁止。

### 6. 分开路由提交与退役清理，按提交点恢复

固定发布集合为提供器、生命周期（含来源快照）、扫描结果、环境代理项和注册表；基础配置是第六项只读基线，不因日常发布改写。待提交记录另含阶段、旧/新字节哈希、权限、存在/缺失状态、生产启动身份、generation 与退役请求。记录和副本先同步文件及目录，目标同目录原子替换；不把多文件替换称为原子事务，也不引入通用框架。

**路由发布：** 校验完整候选与所有槽身份，新增替代先写提供器并核验，必须保留全部旧身份；关联状态先准备，注册表最后原子提交。ENV 文件仅替换原代理项，未知内容与缺失状态保留；运行中的全局候选以注册表栅栏过滤，不能靠 ENV 自动热加载。提交前尚无消费者可使用新槽；显式引用冲突阻止该槽分配。注册表提交后旧节点进入排空阶段，不能等待到全部排空才提交替代路由。

**退役清理：** 属于已提交版本之后的独立受管阶段，注册表版本不回退；记录本次确认和物理清理目标，再刷新提供器移除已排空节点。清理未满足条件或超过本轮预算仅留下待退役原因，路由发布成功与物理回收完成分别记录，不能把“路由已提交”写成“已回收”。

| 中断窗口 | 恢复行为 |
| --- | --- |
| 提供器新增后、注册表提交前 | 旧可见路由和身份完整保留；恢复旧固定发布快照，仅通过提供器刷新撤回未提交新增，核验后继续；不加载基本配置。 |
| 注册表提交后、清理前 | 核验已提交新路由并向前收尾，保留旧物理节点；以当前进程重新请求排空，不能回滚到已关闭的旧准入。 |
| 移除旧节点/reject 后、清理记录未完成 | 根据实际提供器哈希及组身份向前核验完成清理；旧确认不能证明新进程排空，槽复用前重新确认当前消费者，无法确认则冻结槽。 |
| Controller 拒绝/超时/响应丢失 | 先读取实际提供器/组身份区分已生效、未生效和未知；验证旧可见路由始终可用。结果未知保留记录并非零退出，不 fallback restart。 |
| 外部修改、非旧/新哈希、生产启动身份变化 | 停止发布和回收，保留证据；不覆盖外部修改或自动重启。 |

成功的来源成员差分只随完整提交落盘，未完成扫描不将本轮部分结果写为最终状态。每轮先处理遗留发布记录，再启动新探测；待退役等待不妨碍其它安全节点更新。若新轮路由版本改变，旧排空确认失效，按当前版本重新请求。

### 7. 分层验收，逐项可证伪

| 层级 | 通过证据 |
| --- | --- |
| 单元/行为 | 保留已有红复现；身份改名/排序不变，TLS/认证/传输修改产生新身份，多来源差分/失败保留；引用取得与版本更新竞争、取消/异常/重试、空闲回收与 SSE、producer 独立计数、固定引用及过期确认均有可复现行为断言。 |
| Linux 实际集成 | 同版本实际 Mihomo、实际托管客户端/验证码生命周期和真实回环 TCP/SSE；旧流正常非空 DONE，新业务自动转同区替代，未排空不删、排空后 reject/安全复用；完整扫描/发布/恢复及 watcher/Update 竞态无更新器造成的连接失败。 |
| 容量与恢复 | 测试配置的全部大区槽范围、端口冲突、满槽拒绝/回收后再分配；采集峰值 RSS/FD、启动及周期耗时。逐点文件失败、响应丢失、SIGTERM/强制退出、网关重启/worker 变化均符合恢复契约；隔离原型不是最终峰值结果。 |
| 首次维护 | 无在途/共享消费者冲突，有私有回退；记录准入暂停、部署/加载、协议及基础结构验证、恢复服务的完整区间；维护暂停不计作日常更新连续性通过。 |
| VPS 日常 | 维护完成后经实际客户端入口覆盖整轮扫描与发布/退役；有效验证码、非空模型终态及请求 ID 对齐 journal/监控，原 PID/监听/基础哈希不变，无更新器导致的 503、连接失败或短参数失败。 |

测试导入前设置临时数据与禁用 dotenv，替换全部文件和网络目标；Windows skipped 不算 Linux 通过。所有故障注入仅在隔离实例。真实额度前提只读检查，不足就标记模型验收受阻，不改账号、不用空响应充数。Antigravity CLI 规划审查、最终源码验收、Linux 和 VPS 实证分别绑定当次制品。

## Risks / Trade-offs

- [固定全量槽资源与冲突] → 复用已配置百位段，不硬编码真实路径/端点；实测全部槽及峰值，失败不迁移或强占。
- [所有来源失败/没有同区替代] → 保留最后有效快照及明确标记后备，后续有效轮次重评；缓存不能保证外部可用性。
- [没有消费者确认或旧流长期未结束] → 保留节点与等待原因，不靠任意超时强删；可用容量受限是明确代价。
- [提供器 watcher 与多文件中断] → 替换前候选完整安全，私有阶段记录与实际身份核验，注册表提交后向前恢复。
- [进程重启或未知固定端口消费者] → 确认绑定启动身份/版本；集合变化重新确认，不将过期零计数作为回收依据。
- [一次维护暂停] → 用户已接受，预演与私有回退限定范围；网关与代理协议必须一起转换，日常脚本无生产停启权限。

## Migration Plan

1. 实施前重新核对项目业务、全部后台任务、实际服务/worker 和共享 Mihomo 消费者；故障 timer 保持暂停，记录有效配置、启动身份和文件哈希，私有备份代码/状态/单元并核验权限及恢复方式。
2. 完成最小源码修改、对应测试/既有 docs 和 Linux 实际集成、容量、恢复验证；提交当前制品给真实 Antigravity CLI 验收。维护不绕过任何源码或隔离门禁。
3. 按既有原目录 Git 流程传输制品，推送/拉取快进并核验提交与运行文件哈希；在一次维护窗口关闭业务准入、停相关后台、排空旧操作及 Node 子进程，确认共享消费者安全后，统一部署网关协议和固定槽/provider 基础配置。
4. 验证完整槽身份、空槽 reject、当前消费者协议/启动身份及无敏感输出；按原服务方式启动业务，实测短请求和正常 SSE。失败留在维护并用私有备份回退，不能带故障恢复 timer。
5. 维护结束后手工完整周期与真实连续业务重叠；符合日常连续性、订阅差分/退役和幂等条件后完成最终 CLI 复核、OpenSpec 验证、原子提交与发布核验，再恢复原 timer 状态并记录下一触发。回退旧缺陷版本必须保持 timer 暂停；回退需要基础结构变化时再进入明确维护，不能伪装日常恢复。

## Open Questions

无影响范围、迁移路线或验收口径的未决选择。暂停时长、实际资源峰值、消费者清单和运行状态须在实施任务中重新测量，结果记录在 implementation；设计本身不能作为运行验证证据。
