# Spec: plugin-usage-shadow

## 1. 契约与范围

定义 plugin 通道的**额度读数旁路对照**：周期性读取插件的 `usage`，结果只落库供比对，
**对 zcode2api 的任何决策零影响**。

范围：`app/channels/plugin_channel.py` 的 `usage()` 调用点、`app/routes/gateway.py` 或
`app/quota.py` 的旁路写入点。

---

## 2. 为什么是"旁路对照"

现有 `quota.py` 的额度判定（套餐识别、桶剩余量、耗尽判定）**已经过用户确认并落地**：
- "所有 balances 桶都用完才算 exhausted"
- 时间格式统一 `MM-DD HH:MM`
- 状态文案归一化

**直接替换成插件读数会引入格式与语义风险**（插件返回 magpie 卡片格式，且 `-Trial` 与普通消耗计入同一窗口）。

**因此**：先**并行读取、只做比对**，确认两边数字一致后再考虑替换；**本次不替换**。

---

## 3. 需求与场景契约

### REQ-SHADOW-01: 仅旁路写入，不参与决策
- **场景 1（零影响）**：`usage` 的结果**严禁**用于：账号状态判定、选号、耗尽判定、额度展示。
- **场景 2（失败隔离）**：`usage` 调用失败（超时/异常/通道不健康）时，
  **严禁**影响账号状态、请求路径或任何既有逻辑；仅记录一条 warn 日志。

### REQ-SHADOW-02: 触发时机
- **场景 1（复用既有节奏）**：随现有账号轮询触发（复用 `ZCODE_QUOTA_REFRESH_INTERVAL`，默认 60 s）。
- **禁止**新增独立定时器。

### REQ-SHADOW-03: 存储
- **场景 1（位置）**：写入既有 DB `meta` 表，键名 `plugin_usage_shadow`。
- **场景 2（内容）**：JSON 字符串，须含 `at`（时间戳）与 `accounts`（槽位 → usage 原始返回）。
- **禁止**新增数据库表。

### REQ-SHADOW-04: 数据形态（实测）
- **场景 1**：`usage` 返回形如：
  ```json
  {
    "plan": "ZCode Start Plan",
    "until": "2026-10-18T15:59:59.000Z",
    "windows": [
      {"name": "GLM-5.3", "used": 3358, "limit": 3000000,
       "display": "3358 / 3000000", "resetsAt": "2026-10-15T15:59:59.000Z",
       "span": 86400, "models": ["glm-5.3", "GLM-5.3-Trial"]}
    ],
    "error": "",
    "signIn": "kept"
  }
  ```
- **场景 2（原样保存）**：**必须原样保存**插件返回，**不做格式转换**（转换会引入两边不一致的风险）。

### REQ-SHADOW-05: 已知边界（必须记录，不得掩盖）
- **场景 1（无法细分池）**：`usage` 把普通与 `-Trial` 消耗**计入同一窗口**，
  无法从读数区分"花在 start plan 还是活动额度"。**接受此限制**（对照目的是总量一致性）。
- **场景 2（非权威源）**：`usage` 是插件的读数，**不是** zcode2api 的额度权威源。

### REQ-SHADOW-06: 通道不健康时跳过
- **场景 1**：plugin 通道不健康（Bun 缺失 / host 未就绪）时**直接跳过**本次对照，不重试、不告警升级。

---

## 4. 验收标准

| 编号 | 验收 |
|---|---|
| AC-S1 | 开启对照后，账号状态/选号行为与改动前**完全一致**（回归测试） |
| AC-S2 | `usage` 抛异常时，请求路径与账号状态**不受影响** |
| AC-S3 | DB `meta` 表出现 `plugin_usage_shadow` 且为合法 JSON |
| AC-S4 | 内容含 `at` 与 `accounts`；原始格式未被改写 |
| AC-S5 | 未新增数据库表 |
| AC-S6 | 未新增定时器（复用既有轮询） |
